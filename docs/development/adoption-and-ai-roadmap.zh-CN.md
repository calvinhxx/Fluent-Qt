# 采用与 AI 交付路线图

[English](adoption-and-ai-roadmap.md) | 简体中文

## 目的

FluentQt 1.7 已补齐主要组件、无障碍、绑定、WebAssembly 和发布流程。
下一步重点是采用：让新用户或 Agent 能快速选用 FluentQt、运行第一个窗口，
并持续产出达到 Gallery 水准的界面。

本路线图把 AI 支持视为完整交付闭环，而非单纯增加文档。阶段表示证据层次，
不是必须串行完成的功能清单；实际工作按下面的精简队列推进。

## 产品边界

FluentQt 继续定位为 MIT 许可、面向 Qt Widgets 的原生 C++ Fluent 组件库，
并提供可选的 PySide6 和 WebAssembly 交付。主要场景包括：

1. 改造现有 Qt Widgets 应用；
2. 为 CLI、TUI、服务、数据工具或 Agent 添加原生桌面客户端；
3. 在 PySide6 中复用同一套原生组件实现。

本路线图不引入第二套设计语言，不增加 QML 或移动端渲染器，不承载应用业务
逻辑，也不提供托管式源码采集服务。项目源码、截图和使用数据只在用户明确选择
后采集。

## 核心指标与辅助指标

核心指标是：**每月成功运行 FluentQt 窗口且经过核验的外部仓库数**。
Star 和页面访问量只能反映曝光，不能代表接入成功。

辅助指标：

| 指标 | 扩大推广前的目标 |
|---|---:|
| Doctor 通过后，首次窗口试跑的中位耗时 | 低于 10 分钟 |
| Quick Start 完成率 | 不低于 80% |
| Agent 在基准任务中的构建成功率 | 不低于 85% |
| Agent 工作流完成率 | 不低于 80% |
| 盲测视觉评分 | 每项不低于 4/5 |
| 相较无辅助基线的成对偏好率 | 不低于 70% |
| 独立成功接入 | 至少 3 个 |
| 已验收基准运行中的未解决阻塞项或重大问题 | 0 |

这些数字是 FluentQt 自身的阶段门槛，不是行业基准。只有记录了仓库、命令、
结果和评审证据的运行才计入统计。
计时从 Qt 与 FluentQt 已可用、Doctor 可以通过后开始；包获取和安装耗时在分发
证据中单独记录。

## 精简执行队列

当前只保留三项 P0 工作，并限制同时进行一项工程改动和一项真实验收：

1. 随下一次合入 `main` 发布已生成的 API Explorer，并确认公开入口与组件深链；
2. 只运行现有 `agent-run-workspace` 任务的 Codex、Claude Code、Cursor 三组
   真实盲测；先根据结果改 Skill，再决定是否需要第二个任务；
3. 协助三个外部项目接入，把重复失败转成诊断、Starter 或组件修复。

P1 只做已被真实接入触发的生产证据：启动/内存、DataGrid 大模型、WebAssembly
首屏、macOS VoiceOver，以及简洁的 ABI/Qt 支持策略。其余项目统一放入“证据触发
后再做”：另外四套跨 Agent 任务、高级 Inspector 对齐/滚轮探针、NVDA/Orca、
多平台像素通道、多个包管理入口，以及探索队列。这样避免在没有用户样本时先建
一套维护成本很高的评测基础设施。

## 阶段 0：基线与契约

已完成：

- 以 1.7 的组件和质量收口结果作为工程基线；
- 生成式目录已收录 69 个组件、90 条路由和 205 个示例；
- 可移植 Skill 已定义 Codex、Claude Code 和 Cursor 的基准运行方式；
- Release、PyPI、TestPyPI、Gallery 和官网事件作为证据来源；
- 本文明确采用门槛和隐私边界。

阶段门槛：路线图和指标可以独立评审，不再把仓库文件清单当作 AI 端到端质量
已经达标的证明。

## 阶段 1：首次成功

### 1A. 环境诊断

状态：已完成。C++ / Python 诊断、版本化 JSON Schema、源码包覆盖、开发包
安装、单元测试和原生 CI 预检均已落地。

提供仅依赖 Python 标准库、只读的 C++ / Python 环境诊断工具。它需要输出简洁
的人类可读结果、供 Agent 使用的稳定 JSON、可执行的修复建议，并且只在存在
阻塞项时返回非零退出码。

验收标准：

- C++ 检查 CMake 3.16+、编译器，并通过真实消费项目的方式查找 Qt Widgets；
- Python 区分已有发布 Wheel 和仅支持源码构建的版本，并检查 PySide6 与
  FluentQt 是否可导入；
- 不发起网络请求，只在临时目录中生成探测项目；
- 单元测试无需安装 Qt 即可覆盖可用和阻塞路径；
- 源码包包含完整诊断工具。

### 1B. 项目创建

状态：已完成。[完整 CI #32654501221](https://github.com/calvinhxx/Fluent-Qt/actions/runs/32654501221)
在 Linux x64/ARM64、Qt 5/6、macOS 和 Windows 的五个 C++ 干净消费环境中均产出
通过报告，完成率 100%，首次窗口中位耗时 9.692 秒；Linux、Windows、macOS 的
三条 Python Wheel 通道同样全部通过，中位耗时 0.546 秒。八份报告均进入真实
窗口路径且没有 blocker。

可移植命令、四套 C++ / PySide6 Starter、架构清单、版本化输出契约、源码包/
开发包交付和 CI 验收任务均已落地。两套 C++ Starter 已通过安装包路径完成编译、
应用层测试和无界面 GUI 冒烟；Python Starter 已完成语法检查并实际执行应用层
测试。独立 Skill 安装包也已包含 `doctor`、`create` 和四套 Starter。
`fluentqt trial` 把诊断、创建、构建、测试和真实窗口 show 路径组合成版本化报告。
快速 CI 只选 3 条代表性 C++ 通道；完整 CI 固定选上述 5 条。所有任务复用现有
构建产物，只编译很小的生成工程，不重复构建 FluentQt。

环境诊断输出稳定后再增加 `fluentqt create`。维护两套明确的 Starter，而不是
生成一个空壳：

- 现有 Qt 项目的接入切片；
- 全新原生工作台，包含 app、application、domain、infrastructure、ui 分层，
  Light / Dark 品牌主题、测试和 CI。

生成的项目不能依赖需要手工修改的绝对路径。C++ Starter 是主实现；Python
Starter 保持相同的产品结构，但不机械照搬 C++ 所有权细节。

### 1C. 可搜索的公开 API

状态：本地验收完成，等待随下一次合入 `main` 发布到 Pages。API Explorer 已覆盖
目录中的 69 个组件和 114 个安装头文件，支持搜索、分类筛选、C++ / Python
名称、声明、聚焦测试和 Gallery 路由。WebAssembly Gallery 深链已在本地完成
编译，并能直接打开指定的 DataGrid 页面。`release/1.7.x` 的完整 CI 会生成站点
产物，但生产 Pages 只从 `main` 发布，因此当前不把本地文件或 CI 产物记作公开
上线。生成过程直接校验安装头文件白名单与现有 AI 目录，不再维护第二份手写索引。

为已安装的公开头文件生成 API 文档，并把目录中的每个组件链接到对应声明、
Gallery 路由和聚焦测试。Quick Start 只保留任务导向内容，不承担完整 API 手册
的职责。

阶段门槛：在 Qt 与 FluentQt 前置条件就绪的五个干净消费环境中运行对应 Starter
的 `fluentqt trial`，首次窗口路径的中位耗时低于 10 分钟，完成率不低于 80%。
自动冒烟证明程序进入真实 `show()` 路径，但不代替界面美学验收。

1B 的远端证据已超过上述门槛；阶段 1 仍保持“进行中”，直到 1C 在公开 Pages
上线并完成入口与深链检查。

## 阶段 2：AI 质量闭环

### 2A. FluentQt Inspector

状态：公共 v1 已完成本地验收。已安装的 C++ API 与
`fluentqt.inspect_widget(...)` 共用同一套只读原生实现和版本化 JSON 报告；生成的
C++ / PySide6 Workbench 也可通过 `--quality-report` 输出同一报告，且两套全新生成
工程的命令行路径均已通过真实运行测试。当前规则覆盖文本裁切、无障碍
名称、桌面点击区域、焦点可达性、重复语义操作、嵌套滚动边界，以及可选的 4 px
布局网格检查。Gallery 场景验收已消除结构性滚动容器、可选择静态文本、焦点代理
和显式滚动链契约的误报。7 个 Gallery 场景与 6 个由 C++ / PySide6 Workbench
模板生成的场景当前均为零发现。内部 finding 对象仍保持私有，避免规则演进扩大公共
兼容面；应用证据已不再只依赖 Gallery。基线/视觉对齐与运行时滚轮边界探针继续
延期，待组件语义足够明确且误报可控后再加入。

基于现有调试图层提供可选的应用检查器，首版输出以下机器可读证据：

- 文本被裁切或省略，但没有可访问的完整值；
- 焦点顺序、无障碍名称和最小点击区域；
- 4 px 间距、基线和对齐异常；
- 多个可见入口绑定到同一语义操作；
- 滚动归属和嵌套滚动的边界行为。

Inspector 只报告证据，不自动改写应用界面。

### 2B. 应用场景

状态：自动化部分已完成，手动输入法验收待执行。v2 JSON Schema 已为 Gallery
和两套 Workbench Starter 定义 14 个场景：13 个自动化场景覆盖 Light / Dark、
宽 / 窄 / 最小窗口、空状态、加载、错误、长文本、密集数据和滚动边界，另有 1 个
手动输入法组合场景。C++ 与 PySide6 Starter 的空工作区都使用真实控制器状态和
可执行的重试路径，不再列为延期项。

定义可复用的应用场景清单，覆盖 Light、Dark、窄窗口、最小窗口、空状态、
加载、错误、长文本、输入法、密集数据和滚动边界。所有场景都运行在真实应用
上，而不是示意图中。

### 2C. 跨 Agent 基准

状态：进行中。第一个 `agent-run-workspace` 任务已有固定提示词、运行记录 Schema
和可移植工具，可为 Codex、Claude Code、Cursor 初始化同版本 Skill 的盲测记录，
校验提交、命令、构建产物、Inspector、视觉证据和独立九维评分，并汇总三次运行。
汇总在没有人工成对偏好结果时只会标记为 `awaiting-preference`，不会误报通过。
尚未完成的是三次真实运行和人工盲测。其余四个仓库任务不再是当前门槛；只有
首个任务暴露出无法覆盖的不同接入形态时，才增加第二个。

使用同一个版本化 Skill，让 Codex、Claude Code 和 Cursor 先完成同一个仓库
任务。公开提示词、提交、命令、截图、失败记录、九维盲测评分和成对偏好结果。
确定性的目录测试只用于验证检索，不能当作模型能力或视觉质量证明。

阶段门槛：本文定义的构建、工作流、视觉、偏好和阻塞项指标全部达标。根据运行
记录删除或推迟对结果没有实际帮助的 Skill 指令。

## 阶段 3：生产证据

P1 交付内容：

- 可重复的启动耗时、内存、DataGrid 大数据模型和 WebAssembly 首屏测试；
- 先完成 macOS VoiceOver 实机验证；Windows/Linux 有真实使用者或维护者后，
  再增加 NVDA 和 Orca；
- 简洁的 ABI、弃用和 Qt 支持策略；
- 视觉感知通道、包体积/滚动专项和额外包管理入口仅在真实回归或接入需求出现后
  增加，审美变更继续由人工确认。

阶段门槛：所有结果均有版本、可复现，并能从 Release 直接访问。

## 阶段 4：外部采用

围绕真实证据推进。前三个外部接入现在就开始，不等待阶段 3 全部完成：

1. 协助三个独立项目完成接入，并记录失败步骤；
2. 把重复问题转化为诊断工具、Starter、目录或组件修复；
3. 发布迁移、大数据和跨 Agent 基准案例；
4. 增加经过核验的“Built with FluentQt”展示；
5. 通过范围明确的 Issue 和组件负责人降低单维护者风险；
6. 仅在 Quick Start 和接入指标达标后扩大推广。

阶段门槛：至少十个外部仓库成功运行 FluentQt 窗口，三个接入经过独立核验，
并且至少三人贡献了有效代码或文档。

## 探索队列

以下方向需要阶段 1–4 的证据支持，暂不列为承诺：

- Qt Designer 自定义控件集成；
- Figma 变量、组件和语义 Token 导出；
- 基于成熟 Qt Docking 库的工作台方案；
- 可选 MCP，用于实时查询目录、启动 Gallery、构建、诊断和截图评审。

静态指南、模板和参考素材继续放在可移植 Skill 中。只有需要读取实时状态或执行
操作时，才引入 MCP 或 Plugin。
