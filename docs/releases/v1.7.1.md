Fluent-Qt 1.7.1 makes the project easier to evaluate and adopt, while making
the stable Python publication path safer and recoverable.

## Website and onboarding

- The project site now serves an English homepage at `/` and a Simplified
  Chinese homepage at `/zh-CN/`, with ordinary language links instead of
  browser-language redirects.
- The homepage gives C++/Qt Widgets, Python/PySide6, and online Gallery users
  distinct starting points, while clearly separating browser evaluation from
  the Qt development environment required for application integration.
- Canonical URLs, reciprocal `hreflang` links, localized Open Graph metadata,
  JSON-LD, a sitemap, and URL-owned 404 behavior improve international search
  discovery without changing a page's language in JavaScript.

## Community entry points

- GitHub Discussions now has structured Q&A, ideas, and show-and-tell forms so
  questions, proposals, and project examples arrive with useful context.
- Issue and pull-request templates, support guidance, the Code of Conduct,
  security policy, and contribution guidance make the expected public and
  private reporting paths explicit.

## Release reliability

- Stable GitHub Releases now wait for the immutable Python candidate to finish
  before publication, so desktop assets cannot become public while the wheel
  matrix is still incomplete.
- TestPyPI and PyPI publication use the same verified 18-wheel bundle, with
  manifest and hash checks at each promotion boundary.
- Interrupted post-tag TestPyPI publication can resume from the original
  Release bundle without rebuilding or replacing immutable package files.
- Workflow boundary checks now lock the release dependency graph and keep
  candidate validation separate from package-index publication.

There are no FluentQt runtime API changes in this patch release.
