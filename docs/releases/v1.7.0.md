# Fluent-Qt 1.7.0

> **Status:** Historical release note

Fluent-Qt 1.7 makes the project explicitly Fluent-only, completes the
contract-first Field and DataGrid work, and strengthens overlay,
accessibility, Gallery, and AI-assisted development quality gates.

## Fluent-only product contract

- Fluent is now the only component geometry and interaction language across
  Windows, macOS, Linux, and WebAssembly.
- Material and Cupertino design-language enums, paint branches, Gallery
  choices, assets, tests, documentation, and PySide6 bindings have been
  removed instead of retained as one-value or no-op compatibility shells.
- Light/Dark themes, semantic token snapshots, accent customization, and the
  optional `fluent.json` override remain supported through `ThemeRegistry`
  and `UserTheme`.
- Mica/Acrylic backdrops and native platform window integration remain. They
  are platform capabilities, not alternate component design languages.

## Components and behavior

- `Field` provides a value-neutral label, required indicator, editor slot,
  helper text, validation presentation, focus, and accessibility composition
  shell in C++ and PySide6.
- `DataGrid` provides a caller-owned model/view table with bounded visible-cell
  work, column interaction, selection, accessibility, delegate editing, and
  validation support in C++, PySide6, and the WebAssembly Gallery.
- `TextEdit` keeps max-line content fully readable across overflow, width
  changes, and Light/Dark transitions; Tab-to-focus remains an explicit opt-in.
- `ListView` can hide its selection indicator without changing the selected
  item or selection model.
- Popup, Flyout, Dialog, ContentDialog, TeachingTip, and related surfaces use
  documented logical-open, lifecycle, close-reason, modal, dim, and close-policy
  contracts.
- The accessibility inventory covers all public visible components, with
  focused contracts for composite collections, navigation, values, overlays,
  pickers, and semantic presentation.

## Gallery and AI-assisted development

- C++ and PySide6 Galleries expose the same component catalog and teaching
  scenarios; the WebAssembly Gallery keeps bilingual C++/Python source while
  executing native C++ previews.
- The cross-agent `build-fluentqt-gui` Skill now includes design briefs,
  project-structure templates, concise copy and icon guidance, Light/Dark theme
  derivation, and independently reviewed visual evidence.
- The generated component catalog and retrieval/composition evaluations now
  describe only the Fluent contract.
- Representative Light, Dark, and RTL visual baselines remain an opt-in local
  approval gate rather than a host-dependent CI pixel job.

## Breaking migration from 1.6

This is an intentional one-time breaking cleanup made before broad adoption.
There are no forwarding aliases for the removed design-language APIs.

| Removed surface | Use in 1.7 |
| --- | --- |
| `FluentElement::DesignLanguage`, `DesignFluent`, `DesignMaterial`, `DesignCupertino` | Components are always Fluent; use `FluentElement::Theme` for Light/Dark |
| `ThemeRegistry::designLanguage()` / `setDesignLanguage()` | Semantic `ThemeRegistry` snapshots and Light/Dark theme state |
| `StyleTheme` / `StyleThemeCatalog` | `fluent::UserTheme` and semantic token customization |
| PySide6 `DesignLanguage`, `StyleTheme`, `current_design_language()` | `Theme`, `current_theme()`, and `theme_tokens()` |
| PySide6 `apply_style_theme()` | `apply_user_theme()`, `set_accent_color()`, and `reset_theme_tokens()` |

An existing Gallery `settings/styleTheme` preference is ignored and the
Gallery starts in Fluent. Former Material/macOS user theme files are preserved
on disk but are no longer read. See the
[Fluent Design Contract](../design-languages/README.md) for the complete
migration table.

## Compatibility

- Compatibility from 1.7 onward follows the concise
  [public API, ABI, deprecation, and Qt support policy](../development/compatibility-policy.md).
- The native C++ baseline remains C++17 with Qt 5.15+ or Qt 6.2+.
- PySide6 remains optional. Source compatibility still starts at Python 3.10
  with Qt/PySide/Shiboken 6.2.4; official wheels target Python 3.11-3.13 with
  the documented matched toolchain.
- Existing applications that used only the default Fluent path and Light/Dark
  theme APIs retain their component behavior. Applications that referenced the
  removed design-language or style-theme APIs require source changes described
  above.
