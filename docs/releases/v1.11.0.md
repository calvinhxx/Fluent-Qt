Fluent-Qt 1.11.0 makes particle effects an optional module, adds custom-font
support to FontIcon, and reduces repeated work in the 3D Gallery and release
pipeline. The website now explains version changes and migrations in English
and Chinese. Particle users need the source migration described below.

## Breaking change: particle module extraction

Particle effects are no longer part of the base Widgets library. This is an
explicitly approved compatibility exception for 1.11: the old layout headers,
namespace, and Python imports are removed without forwarding aliases.

| Previous integration | Use in 1.11 |
|---|---|
| Link only `FluentQt::FluentQt` for particles | Request and link `FluentQt::Particles` |
| `<FluentQt/Layout.h>` or the former layout declaration header | `<FluentQt/Particles.h>` |
| `fluent::layout::ParticleBackdrop` | `fluent::particles::ParticleBackdrop` |
| `from fluentqt.layout import ParticleBackdrop` | `from fluentqt.particles import ParticleBackdrop` |

Enable `FLUENT_QT_BUILD_PARTICLES=ON` when integrating from source. Installed
SDK consumers use:

```cmake
find_package(FluentQt CONFIG REQUIRED COMPONENTS Particles)
target_link_libraries(my_app PRIVATE FluentQt::Particles)
```

The CPU backdrop does not require OpenGL. Spatial brings in Particles for its
GPU layer, while base package discovery stays independent of these extensions.

`ParticlesSession` manages shared activation and temporary suspension. Pausing
a session preserves the backdrop's `animationEnabled` preference; use
`isAnimating()` to observe whether it is currently running. Destroying a session
releases its suspension, and overlapping sessions resume a backdrop only when
all suspension owners have released it. Call `setAnimationEnabled(false)` when
the application intends to leave animation disabled.

## Draw icons from application fonts

`FontIcon::setFontFamily()` selects an application-provided font and paints the
supplied Unicode glyph at the requested pixel size. Applications register fonts
through `QFontDatabase` and pass the returned family name. Custom fonts bypass
the Fluent catalog and optical-size substitution; theme colors, disabled state,
rotation, and supplementary Unicode glyphs remain supported.

Leaving the family empty preserves the existing bundled Fluent icon behavior.
C++ and PySide6 Gallery include matching examples, and the website documents
font registration and the new property.

## More efficient rendering and reliable interaction

The 3D Gallery updates damaged texture rows, limits cached rendering memory,
and restores sharper rendering after interaction stops. Sustained slow rendering
can return to the native 2D view instead of continuing to accumulate expensive
frames.

Open overlays follow changes to their host surface. Scrollbar thumbs align
their painted geometry with native hit testing. PySide6 extension widget
creation and cleanup enforce their ownership boundaries more consistently.

## Releases and documentation

The website has bilingual release summaries, migration examples, and a roadmap.
Readers can filter changes by component and installed version. API pages flag
related changes that have not yet reached a stable release. Missing translations
or stale reviewed summaries stop generation instead of silently publishing
incomplete records.

Documentation and component captures are generated from current source and
validated together with the matching browser Gallery. Canonical artwork and
verified font-generation inputs are reused instead of maintaining duplicate
tracked copies.

## Build and delivery

Python releases use one stable-ABI native wheel per platform and architecture.
The six build lanes still install and test their wheels across the same 17
supported platform/interpreter combinations. This replaces 17 separate native
wheel builds; the shared pure-Python Gallery wheel is distributed alongside them.

Release candidates build desktop packages and Python wheels once, before the
tag, and publication promotes those exact artifacts. Compiler parallelism is
bounded by the configured runner budget. Static website-only changes can use
the website validation lane without unrelated native or browser builds.

Desktop Debug builds use release Qt dependencies by default while retaining
debug information for project code. Set `FLUENT_QT_DEBUG_RELEASE_RUNTIME=OFF`
when a matching debug Qt runtime is required.

C++17, Qt Widgets 5.15+ or 6.2+, and the pinned Qt 6.9.3 WebAssembly toolchain
remain supported. Official Python wheels target Python 3.11–3.13, with the
existing Python 3.12 floor on Linux ARM64. Rebuild native consumers with the
matching Qt/toolchain when upgrading; a stable C++ binary ABI is not promised.
