# Fluent-Qt 1.9.0

> **Status:** Historical release note

Fluent-Qt 1.9.0 adds an optional Spatial module for composing existing Qt
Widgets in perspective, with an interactive 3D Gallery on desktop and
WebAssembly. It also improves rendering, input, and animation when widgets
are drawn through transformed surfaces.

## Compose widgets in depth

`SpatialView` hosts ordinary Fluent controls, cards, and charts. `SpatialItem`
sets the position, rotation, depth, and surface finish of each hosted widget.
Their children keep their existing signals, layouts, and model contracts.
Switching back to 2D preserves the same content and interaction state.

Spatial is an opt-in `FluentQt::Spatial` target, enabled with
`FLUENT_QT_BUILD_SPATIAL=ON`. The base `FluentQt::FluentQt` target keeps its
Qt Widgets dependencies. Spatial adds Qt OpenGL support; it does not require
Qt Quick or Qt 3D. It composes flat widget surfaces rather than loading 3D
meshes. See the [Spatial guide](../architecture/spatial-view.md) for integration
and supported content.

PySide6 source builds can enable the same module and import it from
`fluentqt.spatial`. The standard PyPI wheels retain the base 2D API; enable
Spatial in a matched source build to use the Python 3D Gallery.

## A shared 3D Gallery experience

Spatial-enabled C++, Python, and WebAssembly Galleries use **Settings → 3D
Gallery** to control both the application shell and the component examples.
First launch prefers 3D when hardware acceleration is available. A saved 2D
choice is preserved, and unavailable acceleration, reduced motion, or high
contrast falls back to 2D.

The title bar stays outside the perspective surfaces. Transformed content
retains keyboard navigation, text editing, and correctly placed popups.
Native overlays receive input before the surface underneath; modal dialogs
continue to block background interaction.

Desktop startup prepares Home, Settings, and the loading shell. Other pages
are built on demand, one sample per event-loop turn, and reused on later
visits. This avoids constructing every component demonstration during launch.

## Rendering and animation fixes

The Gallery caches GPU surfaces so pointer movement can reuse existing
content. Panel textures and optional GPU particles share a bounded memory
budget. Particle backgrounds keep their CPU path when GPU rendering is
unavailable or does not fit the budget.

This release fixes high-DPI scaling, clipping, and text visibility in
redirected widget painting, including AutoSuggestBox input. StackView and
other opacity-based transitions retain their coordinates across GPU paint
strips, avoiding displaced frames and clipping during animation. TreeView
teardown also stops state callbacks from reaching objects being destroyed.

## Compatibility and validation

The supported baselines remain C++17, Qt 5.15+ or Qt 6.2+, with PySide6 6.2+
for the base Python API. Existing applications can keep using the base target
without enabling Spatial.

The local preflight now shares CI's source and packaging checks, and provides
a focused mode for tests owned by changed files. Release validation still
uses the full platform, wheel, SDK, and WebAssembly gates.
