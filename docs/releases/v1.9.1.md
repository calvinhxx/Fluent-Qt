Fluent-Qt 1.9.1 fixes 3D Gallery packaging and startup. Python wheels now
include Spatial, and Windows ARM64 Gallery uses Direct3D 11 for hardware
rendering. Unavailable graphics acceleration returns the application to a
usable 2D interface.

## Python Gallery includes 3D

The 1.9.0 Python wheels omitted Spatial. All supported 1.9.1 release wheels
include its native API and the full Gallery integration. Upgrade both packages:

```bash
python -m pip install --upgrade "FluentQt==1.9.1" "FluentQt-Gallery==1.9.1"
python -m fluentqt_gallery
```

Use **Settings → 3D Gallery** to switch the shell and Spatial examples between
2D and 3D. A fresh installation prefers 3D when hardware acceleration is
available; an existing saved 2D preference is preserved. Reduced motion and
high contrast continue to use 2D.

## Windows ARM64 startup

The Windows ARM64 C++ and Python Galleries now share a Direct3D 11 rendering
path through Qt, using the graphics runtime supplied by Windows. This allows
3D on supported devices and virtual machines that lack a usable OpenGL driver.

On Windows ARM64 with Qt 6.7 or newer, startup checks Direct3D 11 first, then
OpenGL. If neither is available, or the selected renderer fails during
initialization, Gallery restores its native 2D interface instead of leaving a
blank window. The saved 3D preference remains available for a later launch.
Other platforms keep their existing default rendering paths.

## Text visibility and package checks

LineEdit and controls built on it, including AutoSuggestBox, retain their
theme text colors when a parent widget reapplies its style. This fixes text
disappearing against the input background after a theme refresh.

Release checks now require Spatial in every Python wheel and verify Windows
ARM64 runtime architecture, dependencies, and installed application startup.
These checks catch missing modules and mixed-architecture packages before
publication.
